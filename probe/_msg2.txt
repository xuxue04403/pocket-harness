Make the TypeScript core compile under ArkTS instead of only under Node

ArkTS rejects two things the Node build accepted: there is no TextEncoder or
TextDecoder in the HarmonyOS lib target, and `unknown` is a hard error rather
than a lint. Both were real: the first hvigor run failed with thirteen errors
across bytes.ts, pairing.ts and the probe page.

- src/bytes.ts: hand-written utf8/fromUtf8, including surrogate pairs and
  U+FFFD for invalid sequences.
- src/json.ts: JsonObject plus shape-checking accessors, so JSON.parse results
  are narrowed once instead of leaking `unknown` into every caller.
- pairing.ts, wire.ts, link_protocol.ts, rpc.ts: Record<string, unknown> and
  `let parsed: unknown` replaced with JsonObject.
- Live test resolves the probe files from the repo root instead of relying on
  the working directory, so it runs from anywhere.

Verified three ways: the golden vectors still pass, the protocol checks still
pass, and the live client still completes a Noise handshake against the running
Host and reads session/list plus a job/list stream. The HarmonyOS probe now
BUILD SUCCESSFUL with a 189 KB HAP whose modules.abc contains x25519,
NoiseIkSession, createNoisePrologue and decodeTicket.
