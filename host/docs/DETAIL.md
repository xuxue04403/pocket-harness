# Pocket Harness Host

Pocket Harness 让手机在**不经过任何第三方服务器**的前提下操控这台机器上的 DeepSeek Harness。
本插件是链路的主机端：它开一个局域网 TCP 端口，等手机扫码后与自己建立端到端加密通道，
再把手机发来的每次调用原样转给 Harness 自己的 Remote API。

## 它做什么

- **配对**：插件持有本机的一组 X25519 密钥，并把「主机公钥 + 局域网地址 + 一次性口令」
  编码成一个配对二维码。手机首次扫码即完成 TOFU，之后靠设备公钥互相认证。
- **加密通道**：Noise IK（`Noise_IK_25519_ChaChaPoly_SHA256`）双向认证，
  手机是发起方、本机是响应方；握手完成后所有业务帧都是密文。
- **透传**：手机发来的 `namespace/method` 原样交给 Harness 的 Typert Gateway，
  因此工作区、会话、终端、任务、设置这些 Remote API 无需本插件逐个实现。
- **权限**：只有通过握手证明了自己持有已固定公钥的手机，才会被授予 `owner` 身份。

## 它不做什么

- 不把任何数据发往公网；没有中继、没有账号、没有遥测。
- 不读写你的 `cordis.patch.yml`，也不改动其它插件的配置。
- 不记录提示词、文件路径、工具输出或 token 到日志。

## 安全边界

本机私钥与已配对手机的公钥都存放在 Harness 的 credentials 服务里，不落明文文件。
手机端首次扫码时固定主机公钥，之后主机公钥一旦变化，手机会拒绝握手——这是唯一需要
用户手动确认「忘记这台主机」的情形。

## 排障

- 手机连不上：确认手机与电脑在同一个局域网，且系统防火墙允许本插件使用的 TCP 端口。
- 二维码过期：设置页的「手机配对」卡片每 10 分钟自动换一次码，倒计时归零后会刷新；已配对的手机不受影响。
- 想撤销某台手机：在设置页移除该设备，它的公钥会被从信任列表删除。

## 配对页面的访问控制

配对码等于一次性的进门凭证，所以 `/api/pocket-harness/pair` 只对两类请求开口：

- **Host 头必须是回环地址**（`localhost`/`127.0.0.1`/`::1`，带不带端口都行）。端口扫描扫到局域网地址时拿到的是 404，而不是「这里有个配对码」。
- **Origin 必须是同源的**。`localhost:52080` 与 `127.0.0.1:52080` 算同一个读者，但别的端口不算——本机上别的进程不该因为同在这台机器上就能读到这张码。

两个例外是刻意留的。**没有 Origin 的请求放行**：那是本机原生客户端，它本来就能伪造任意请求头，这里拦不住任何东西，只会拦住正当调用。**`dsh-app:` 起源放行**：桌面宿主的页面跑在宿主自定义协议下，Origin 形如 `dsh-app://app`，与 Host 头永远不相等；外部网页无法把 Origin 伪造成这个协议，所以放行不扩大 CSRF 面。这一条是照 `dsh-plugin` 的 `isSameOrigin` 抄的——它踩过同一个坑。

跨站与局域网访问一律回 404 而不是 403：403 等于告诉扫描者「这个路径有东西」。

## 二维码怎么来的

设置卡片里那张码是本插件自己编的，没有第三方依赖：`qr_encode.js` 只有 EC 等级 M 的
40 张版本表，从 `packages/dsh_arkts/src/qr/tables.ts` **机械生成**（`probe/gen-qr-tables.mjs`），
不手抄——手抄过一次「每版本总错纠码字数」与「每块错纠码字数」就串了，v7 以上全部解不出来。

编码器与 `packages/dsh_arkts` 的解码器互为正反，验证方式是往返：
`probe/qr-encode-check.mjs` 把文本编成矩阵，再用 `decodeMatrix` 读回来比对。它也单独覆盖
八种掩码与 v7 以上的版本块位序（那两处一旦写反，小版本全对、大版本全错）。
